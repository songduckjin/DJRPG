# MARKET — 공용 거래소

> **책임**: 계정 공용 거래소(판매 등록·묶음·구매·취소·수령함·시세). 저장·멱등은 `docs/SYNC_SAVE.md`, 아이템·가방 40칸은 `docs/INVENTORY_GEAR.md`, 캐릭터 전환 가드는 `docs/SYNC_SAVE.md`.
> **핵심 파일**: `src/ui/modals/marketModal.ts`·`src/game/market.ts`·`server/market.mjs`·`server/endpoints/market.mjs`·`src/styles/market.css`·`functions/api/market*.js`·`api/market*.mjs`
> **불변**: 거래소는 **계정 공용**이다(매물·수령함·판매 한도·골드에 `characterSlot` 조건을 달지 않는다). 수수료 5%, 등록 30건, 72시간 만료, 최소가 1골드, 수령함 30건(`INBOX_FULL`). 묶음 최대 10개. 우리 서버가 `save_json`을 직접 고치지 않고 `writeSave` 배치로만 반영한다.
> **테스트**: `node --test tests/market.test.mjs tests/market-actions.test.mjs tests/market-bundle-ui.test.mjs tests/market-view-toggle.test.mjs tests/market-inbox-ui.test.mjs tests/market-index.test.mjs tests/multi-character-market.test.mjs tests/concurrency.test.mjs`

## 이용 방법
- 필드 왼쪽 아래 `상태 → 장비 → 스킬 → 거래소`의 상점 아이콘을 누릅니다. 기존 금빛 선 아이콘 테마를 사용합니다.
- **판매 중**: 이름 검색, 분류·부위·등급·가격·옵션 최솟값 필터, 최신/가격 정렬, 20건 단위 페이지. 상세에서 착용 장비와 옵션을 비교한 뒤 구매를 확정합니다.
  - 수량이 2개 이상인 묶음 매물은 **`개당 N 골드 · 총 N개`**로 표시하고, 상세에서 **`전체 구매(N개)`** 또는 수량을 골라 **`선택 수량 구매`**를 누릅니다.
  - 단건 매물(수량 1)은 예전처럼 `구매 확정` 한 번입니다. 부분 구매하면 남은 수량으로 매물이 계속 판매 중이고, 판매대금은 팔린 만큼(개당 × 수량 − 수수료)만 적립됩니다.
- **거래 완료**: 실제 판매된 가격과 한국 시간 판매 시각으로 시세를 확인합니다.
- **내 거래**: 본인의 판매/구매 기록과 진행 상태를 확인하고 판매 중인 매물을 취소합니다.
- **판매 등록**: 가방의 미장착 장비 또는 미사용 스킬북을 선택하고 정수 골드 가격을 입력합니다. 예상 수령액을 확인한 뒤 등록합니다.
  - 물품 칸은 한 줄에 8칸이고, 같은 스킬북(같은 `skillId`)은 한 칸에 `×N`으로 묶여 보입니다.
  - 칸을 고르면 **모달이 스크롤되지 않고** 아래 고정 카드에서 수량과 **개당 가격**을 정합니다(물품 그리드만 내부 스크롤).
  - 묶음은 **한 번에 최대 10개**까지 등록할 수 있고(보유가 그보다 적으면 보유 수량까지), `최대` 버튼으로 한 번에 채웁니다.
    총액은 개당 가격 × 수량이고, 수수료 5%(골드 단위 올림)와 예상 수령액을 등록 전에 보여 줍니다.
  - 등록된 묶음은 **매물 1건**이며 동시 등록 한도(30건)도 1건으로 셉니다.
- **수령함**: 구매품·취소품·만료품·판매대금을 받습니다. 아이템은 가방에 빈칸이 있을 때 수령할 수 있고, 수령함에 있는 동안 사라지지 않습니다.

## 초기 운영 규칙
- 모든 유저가 같은 매물·판매 기록을 봅니다. 로그인 아이디와 구매자 정보는 공용 목록에 노출하지 않고 판매 당시 닉네임만 표시합니다.
- 게스트는 조회만 가능하며 정식 계정만 거래할 수 있습니다.
- **개당** 고정가 골드 거래, 등록비 없음, 개당 가격 1~1,000,000,000골드(총액도 같은 상한), 판매 성공 시 수수료 5%(골드 단위 올림), 동시 등록 30건·한 매물 최대 **10개** 묶음, 등록 기간 72시간입니다.
- 만료는 거래소 조회/거래 요청 시 서버 시간으로 처리하며 반환은 한 번만 생성됩니다. 별도 스케줄러 없이도 만료한 매물은 구매할 수 없습니다. 취소·만료 시 **남은 수량 전부**가 아이템마다 수령함 한 줄로 돌아갑니다.
- 스트리밍 연결은 약 1초 간격 변경 확인, 재연결 및 2초 간격 조회 보완을 사용합니다. 거래소가 닫혀 있을 때도 활성 탭은 2초마다 수령함을 확인합니다. 탭이 백그라운드이면 조회를 쉽니다.
- 검색 중 새 매물은 `새 매물 N개`로 알리고, 기존 매물의 판매/취소/만료 상태는 위치를 유지하며 구매 버튼을 비활성화합니다.

## 저장 및 거래 무결성
- DB 테이블은 기존 Turso 설정으로 최초 요청 시 자동 생성됩니다. 기존 계정은 저장 revision 0부터 호환됩니다. 기존 버전으로 열어둔 탭은 배포 후 새로고침해야 합니다.
- 등록 시 DB에 저장된 가방에서 아이템을 제거하고 거래소 보관 상태로 옮깁니다. 요청에 전달된 임의의 옵션·가격 변경·골드 값은 구매 계산에 사용하지 않습니다.
- 묶음 매물은 `djrpg_market.quantity`(남은 수량)와 `items_json`(남은 아이템 배열)으로 보관하고, `price`는 **개당 가격**입니다. 기존 매물은 `quantity=1`로 읽힙니다. 부분 구매는 트랜잭션 안에서 남은 수량을 다시 읽어 초과 판매를 막습니다.
- 최신 클라이언트는 미저장 진행 상황을 거래 요청에 포함하여 별도 선행 저장 요청을 생략합니다. 이미 진행 중인 저장만 마친 뒤, 진행 저장과 구매/취소/수령을 하나의 write 트랜잭션에서 처리합니다. 구매자의 골드 차감, 상태 전환, 구매품과 판매대금 수령함 생성이 함께 커밋됩니다.
- 소유권 원장은 거래소·수령함·소비 상태의 기존 아이템을 세이브로 복원하거나, 다른 계정이 가져가거나, 이미 기록된 옵션을 바꾸는 것을 차단합니다.
- 모든 세이브와 거래에 revision 검사를 적용합니다. 오래된 탭의 덮어쓰기는 차단하고 재접속 안내를 표시합니다. 거래 결과가 불확실하면 사냥과 자동 저장을 잠시 멈추고 동일 요청 번호로 재확인합니다.
- 저장과 거래의 응답 유실에 대한 재시도는 중복 처리하지 않습니다. 미수령 거래나 진행 중인 매물이 있으면 캐릭터 초기화를 차단합니다.

## 거래 응답 지연 개선 (작업 54)
- 거래 성공 응답을 받으면 구매 상태·수령함·보유 골드를 즉시 반영하고 목록 재조회는 백그라운드에서 실행합니다. 성공하기 전에 구매 완료로 표시하지는 않습니다.
- 일반 목록 조회는 쓰기 트랜잭션 없이 1개의 읽기 배치로 조회합니다. 만료가 실제로 있을 때만 별도 쓰기 트랜잭션으로 반환 처리합니다.
- 일반적인 구매·판매대금 수령은 트랜잭션 안의 입력 조회 1회 + 변경 배치 1회로 처리합니다. 새 아이템이나 장비 변경이 있으면 필요한 소유권 검증을 추가합니다.
- 스키마 생성은 같은 함수 인스턴스/DB에서 첫 성공 후 재사용합니다. 목록을 읽을 때마다 테이블/인덱스 생성 잠금을 획득하지 않습니다.
- 테스트는 네트워크 요청 수와 DB 배치 수, 늦은 후속 목록 응답에도 즉시 표시되는 동작을 검증합니다. 운영 DB 지역 간 지연이나 모바일에서의 실제 초 단위 체감 속도를 측정한 것은 아닙니다.

## 검증 범위와 한계
- 실제 서비스 DB를 변경하지 않는 로컬 libSQL 통합 테스트 및 클라이언트 저장 조정 테스트를 제공합니다. `pnpm test`, `pnpm run check`, `pnpm run build`로 실행합니다.
- 프로젝트 정책에 따라 브라우저/헤드리스 실기 테스트는 실행하지 않았습니다. 모바일에서 아이콘 간격·스크롤·검색 키보드·두 계정 간 갱신을 확인해야 합니다.
- **기존 게임의 사냥 시뮬레이션과 신규 드랍 생성은 여전히 클라이언트에서 수행합니다.** 이번 구현은 거래 원장과 저장 충돌의 무결성을 보장하는 개발용 경제 기반입니다. 클라이언트를 조작해 새로운 아이템이나 사냥 골드를 생성하는 행위까지 막는 서버 권위 전투/보상 검증은 별도 후속 작업입니다. 공개 경제의 부정행위 방지가 완료된 것으로 간주하면 안 됩니다.
