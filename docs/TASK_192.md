# [작업 192] 다이아 상점·패키지·구매 슬롯

- **목표**: 오른쪽 상점 아이콘에서 다이아 충전 8종과 패키지 상품을 보여준다. 결제 확인 뒤 서버 계정 재화를 지급하고, 다이아로 추가 슬롯을 연다. 전 슬롯 30일 방치·광고 제거는 기능 출시 전 판매하지 않는다. 캐릭터별 삭제 확인과 생성→사냥터 전환 로딩을 추가한다. 배포는 사용자 지시까지 보류한다.
- **임시 상품표**: 다이아 100/300/500/1000/2000/5000/10000/20000개는 각각 1,100/3,300/5,500/11,000/22,000/55,000/110,000/220,000원. 추가 슬롯 500다이아(최대 9칸), 전 슬롯 방치 30일 1,500다이아. 광고 제거는 광고 기능 출시 전 판매하지 않는다. 가격은 배포 전에 재검토 가능.
- **결제**: 토스페이먼츠 결제창형 v2. 주문은 서버에서 계정·상품·가격을 고정하고, 승인 응답 확인 뒤 한 번만 다이아를 적립한다. 키는 Cloudflare 비밀 변수로만 보관한다.
- **DB 확장**: 주문에 상품 ID·통화·결제사·지급 스냅샷을 저장한다. 재화 변동은 고유 지급 원천이 있는 원장에 남기고, 기간제·수량형 패키지 권한은 공용 권한 테이블로 확장한다.
- **범위**: `server/database.mjs`, `server/endpoints/{account,shop}.mjs`, `functions/api/shop.js`, `src/ui/{interface,hud}.ts`, `src/ui/modals/{shopModal,charactersModal}.ts`, `src/styles/{hud,modals}.css`, `tests/{shop,characters,modal-ui,migrate-turso-db}.test.mjs`, `docs/{CODE_MAP,QUICK_PATCH,TASK_192}.md`.
- **캐릭터 삭제**: 현재 선택 캐릭터와 마지막 1개는 삭제 차단. 목록에 가방·착용 아이템 수를 보여주고 이름 입력으로 재확인한다. 삭제 시 해당 캐릭터의 아이템 UUID는 `consumed` 처리해 재도입을 막는다.
- **캐릭터 생성**: 저장 확인부터 API 생성, 페이지 재로딩 직전까지 전체 화면 로딩을 유지한다. 실패 시 로딩을 내리고 오류·재시도를 보여준다.
- **계약**: 구매 권한·다이아는 Turso 계정 테이블에서만 관리한다. 클라이언트 Save로 재화나 슬롯 권한을 변경하지 못한다. 결제 승인 실패와 중복 콜백은 적립하지 않는다. 다른 계정 주문은 승인할 수 없다.
- **겹침 확인**: 작업 146의 DB 이관 코드는 PR #91로 병합됐다. 진행 중인 다른 `[-]` 작업과 수정 파일이 겹치지 않는다.
